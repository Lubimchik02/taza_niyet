# Сервер Taza Niyet (этап 12)

## Что здесь

| Файл | Что делает |
| --- | --- |
| `migrations/…0100_schema.sql` | Таблицы: люди, организации, квесты и команды, записи, отметки, отчёты смен, журнал начислений, друзья, блокировки, чаты, жалобы, уведомления, устройства для пушей, конфигурация, номера портфолио |
| `migrations/…0200_logic.sql` | Серверная логика: вступление в организацию, запись/лист ожидания/отмена, «Я на месте» с геометкой, ручные отметки старшего, закрытие смены, подтверждение координатором, штраф, поиск, рейтинг, дружба, личные чаты, проверка портфолио, удаление аккаунта |
| `migrations/…0300_rls.sql` | Права доступа (RLS): каждый видит только своё; часы и отметки меняются только функциями |
| `migrations/…0400_app_api.sql` | Выборки для приложения: организации, моё членство, квесты, мои записи, список команды, чат по адресу, устройство для пушей; уведомление о новом сообщении участникам |
| `migrations/…0500_push_prefs.sql` | Язык пушей и настройки уведомлений пользователя |
| `migrations/…0600_coordinator.sql` | Кабинет координатора: обзор, заявки, роли, исключение, код приглашения, квесты и старшие, отмена квеста, отчёты смен с деталями отметок, канал, жалобы |
| `functions/push` | Edge Function: уведомление → пуш через FCM |
| `seed.sql` | Демо-данные: 6 организаций Астаны, 18 квестов (только для тестового проекта) |
| `tests/` | Проверка на обычном PostgreSQL: 13 сценариев логики + выборки приложения |

## Главные правила, которые держит сервер (а не телефон)

- Часы и баллы начисляет только координатор через `approve_shift`; напрямую записать в `credits` нельзя.
- Часы старший ставит не больше длительности квеста, шаг 0,5 ч. Ручные отметки помечены `manual` — координатор видит их отдельно.
- Бонус старшему +10 Tz — только после подтверждения; `penalize` — штраф за ошибки.
- Запись: блокировка строки квеста — двое не займут последнее место; пересечения по времени запрещены; при отмене место получает первый из листа ожидания.
- «Я на месте» из офлайн-очереди принимается с временем телефона, но только в окне смены и не «из будущего»; повтор не создаёт дубль.
- Часы человека видны по его настройке; до 18 лет — только друзьям. Личные чаты — только между друзьями; в канал пишет только координатор; блокировка скрывает сообщения и удаляет дружбу.
- Год рождения нельзя поменять из приложения.
- Удаление аккаунта: 30 дней на отмену, затем профиль удаляется, а подтверждённые часы остаются в отчётах организации без имени.
- Проверка портфолио по номеру работает без входа; номер можно отозвать и выпустить новый.

## Проверить локально

```bash
cd supabase/tests
createdb tn
psql -d tn -v ON_ERROR_STOP=1 -f 00_local_supabase_stub.sql \
  $(for f in ../migrations/*.sql; do echo -f $f; done) -f 10_scenarios.sql -f 30_coordinator.sql
# → ВСЕ СЦЕНАРИИ ПРОЙДЕНЫ, КАБИНЕТ КООРДИНАТОРА: ВСЁ ВЕРНО
createdb tn2
psql -d tn2 -v ON_ERROR_STOP=1 -f 00_local_supabase_stub.sql \
  $(for f in ../migrations/*.sql; do echo -f $f; done) -f ../seed.sql -f 20_app_api.sql -f 40_checkin_anywhere.sql
# → API ПРИЛОЖЕНИЯ: ВСЁ ВЕРНО, ОТМЕТКА БЕЗ ГЕОЛОКАЦИИ: ВСЁ ВЕРНО
```

`00_local_supabase_stub.sql` имитирует то, что в Supabase уже есть (`auth.users`, `auth.uid()`, роли). В Supabase его не применять.

## Применить в Supabase

```bash
supabase link --project-ref <ref>
supabase db push            # миграции
# только в тестовом проекте:
psql "$DATABASE_URL" -f seed.sql
```

Ежедневное удаление аккаунтов через 30 дней (расширение pg_cron):

```sql
select cron.schedule('purge-deleted', '0 3 * * *', $$select purge_deleted_accounts()$$);
```
